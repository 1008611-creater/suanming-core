# ADR-0009：地支关系派生与前事解释层的边界

- 状态：已接受
- 日期：2026-09-21
- 相关：[架构说明](../architecture.md)、[产品规格](../product-spec.md)、[规则集](../rule-sets.md)

## 背景

在阶段 8 之前，盘面上能指认的关系只有「五行分值」与「十神」两类，
而命理实践里最常被用来核对盘面是否算对的，恰恰是地支之间的关系：
六冲、六合、三合与半合、相刑（含自刑）、六害、旬空。

这些关系此前散落在两处：

1. `web/engine-adapter.js` 里自带一张旬空表，按日柱查表得出两个空亡地支；
2. 其余关系完全没有实现，判词里凡是提到「冲」「合」的地方，都没有可引用的规则。

这带来三个具体问题：

- **口径分叉**：页面自己算旬空，引擎不产出，两边迟早给出不同结果；
- **不可追溯**：判词提到关系时无法给出 `ruleId`，违反「每条判词都能引用到具体规则」的项目约束；
- **无法解释**：用户看到「这一宫见冲」，既不知道是哪个柱位与哪个柱位，也不知道依据哪一条规则。

同时，「前事验证」这一交付形态需要把结构翻译成用户能自己打标的清单。
如果让页面直接读关系结构自行拼判词，就会出现第二套解释口径。

## 决策

### 1. 关系派生放进引擎，纯确定性，不读时钟

新增 `src/derive/relations.js`，从四柱派生六类关系：

```
clash（六冲）、combine（六合）、trine（三合）、half-trine（半合）、
punishment（相刑，含 self-punishment 自刑）、harm（六害）、void（旬空）
```

- 全部按规则集里的关系表查表得出，表在规则集里，不在代码里写死；
- 不读当前时间、不使用随机数，同一组四柱必得同一份关系；
- 空亡按**日柱所在旬**判定，`xun` 字段给出旬序、旬名与两个空亡地支；
- 每个关系分组携带自己的 `ruleId`；规则集缺某张表时，**该组整体跳过**并记入 `skipped`，
  绝不回退默认值 —— 宁可少给一条，也不给一条无出处的结论。

### 2. 宫位映射与程度分档属于解释层

新增 `src/interpret/past-events.js`，只做「已算出的结构 → 可用经历核对的清单」这一件事：

- **只读不重算**：输入是 `castBazi` 的输出，本层不碰历法、不排盘；
- 需要年份时必须由调用方显式传入 `asOfYear`；缺省就省略流年类条目，
  绝不用「现在」当默认值 —— 否则同一份盘在不同日子会得出不同清单；
- 输出 5–8 条，每条含四要素：判词、推导依据（宫位／十神／关系／`ruleId`）、
  程度三档（轻／中／重，按 R-01）、不确定性说明（按 R-02）；
- 宫位口径（年柱＝祖上宫、月柱＝父母宫、日柱＝夫妻宫、时柱＝子女宫）写在解释层，
  因为它不参与任何计算，只决定判词怎么称呼。

### 3. 适配层不再自带任何算法

`web/engine-adapter.js` 删掉本地的旬空表与旬序推算函数，
`xunKong` 直接取 `chart.relations.xun.voidBranches`；缺表时返回空数组表示「未判定」，
而不是回退到一张页面自己的表。

### 4. 版本与兼容区间

引擎升到 `0.6.0`。四套规则集的 `engineCompatibility` 上界同步放宽到 `<0.7.0`：
本次新增的是**新字段**（`relations`、`pastEvents`），既有字段的取值口径未变，
旧盘结果不漂移。

### 5. 展示层口径（0.6.1 补充）

0.6.0 上线后逐条核对清单，发现三处展示层缺陷。它们都不影响关系命中本身，
但会让用户读到的判词像半成品，因此把口径在这里补齐。

**关系名只出中文。** `kind` 里的 `clash` / `harm` / `void` 是内部枚举。
规则表的每一对／每一组关系必须逐项写明 `name`（`子午冲`、`子丑合土`、`寅巳害`、
`寅巳申三刑`），派生层在规则表漏写 `name` 时兜底为「表内两支 + 关系后缀」，
绝不返回裸地支对 ——「子午」看不出是冲还是合，用户没法拿它去核对经历。
解释层的 `relationLabel()` 再做一层防线：`name` 缺失或含英文时退回类型中文名。
`basis.ruleId` 仍原样露出（`bazi.relation.branch-clash`），那是追溯用的标识，
不是展示文案，二者在页面上分栏显示。

**一条跨柱关系只完整展开一次。** 月支与时支相冲，在结构上确实同时落在父母宫与
子女宫。若两个条目都把它当成自己的发现完整展开，用户看到的就是同一句话写了两遍，
清单立刻显得像在凑条数。口径定为：跨柱关系由**最早一个在清单里有条目的宫位**
（月 → 日 → 时）展开，其它相关宫位只以「共见」引用；年柱不进前事清单，
因此年柱参与的关系一律由月／日／时承接。

**为什么归属口径写在解释层。** 派生层只回答「哪两个柱位构成了什么关系」，
它不区分宫位轻重、也不知道哪些宫位会进清单。归属规则依赖「清单里有哪些条目」，
是解释层的知识，写进派生层会让结构输出带上解释层的取舍。这与第 2 条的分工一致。

## 替代方案

**在页面里派生关系。** 会立刻产生第二套算法，与 ADR-0006「网页单一引擎源」冲突；
Node 端测试全绿而浏览器里结果不同，正是这类分叉最典型的后果。已否决。

**把程度分档放进派生层。** 派生层只回答「哪两个柱位构成了什么关系」，
「这算轻还是重」是流派约定，写进派生层会让同一份关系结构无法被不同解释层复用。已否决。

**缺表时回退到内置默认表。** 违反「缺表即整组跳过」的项目约束，
且会让规则集审计失去意义：用户以为在用 A 规则集，实际拿到的是内置表的结果。已否决。

**流年类条目用当前年份兜底。** 会让同一份盘在 2026 年与 2027 年给出不同清单，
违反确定性约束。已否决，改为必须显式传入 `asOfYear`。

**把跨柱关系在涉及的每个宫位都展开。** 看起来信息更全，实际是同一句话重复出现，
用户会以为清单在凑条数。已否决，改为最早宫位展开、其余共见。

**页面自己把英文枚举翻译成中文。** 会立刻产生第二套术语表，与 ADR-0006 冲突，
且换一套规则集后页面术语会与规则集脱节。已否决，改为关系名随规则表下发。

## 影响

- 判词中凡是提到冲、合、刑、害、空亡的地方，现在都能指回 `ruleId`；
- 页面上「旬空」有了唯一来源，不会再出现两套口径；
- 解释层多了一层可审计的边界：`skipped` 会记录因规则集缺条目而整体跳过的清单项；
- 判词与依据栏只出现中文关系名，用户能直接拿「子午冲」去核对自己的经历；
- 同一条跨柱关系在清单里只完整展开一次，其余宫位以「共见」引用，条数不注水；
- 网页静态资源总量从约 400 KB 升到约 440 KB，性能预算相应上调并写明理由；
- 前事清单是**免费公开**的，不设付费墙；付费点放在人工陪验环节。

## 验证

- `tests/relations-smoke.js`：六类关系黄金样本 + 三类边界反例
  （半合缺旺支、同柱不构成自刑、跨旬空亡）+ 确定性；
- `tests/relations-missing-table-smoke.js`：规则集缺表时整组跳过，不回退默认值；
- `tests/past-events-smoke.js`：条数落在 5–8、每条 `ruleId` 可解析、
  程度档合法、同输入逐字一致、缺 `asOfYear` 时无流年条目、文本不含百分比与「准确率」、
  判词无重复、`basis.relation` 只出中文关系名、展示文本不含内部英文枚举；
- `tests/bazi-cross-reference-smoke.js`：随机抽 10 份盘与独立实现比对四柱；
- `tests/web-adapter-smoke.js`：`xunKong` 与 `relations.xun` 同源，清单随适配层交付；
- `tests/check-page-smoke.js`：前事区块可打标、汇总只写条数、页面文本无百分比；
- `tests/relations-smoke.js`（0.6.1 追加）：遍历每一套四柱规则集，逐项断言冲／合／害
  三张表的 `name` 非空、长度大于 2、不含英文、含对应关系字；黄金盘命中的 `name` 同断言；
- `tests/report-page-smoke.js`（0.6.1 追加）：报告工具源码里不允许出现八个内部关系枚举名，
  命中清单与依据栏都必须取引擎已译好的中文名；
- 真实 Chromium 复核（0.6.1）：前事页判词只出中文关系名、依据栏「关系」后是中文、
  375px 不溢出、控制台零错误、汇总只写条数。
