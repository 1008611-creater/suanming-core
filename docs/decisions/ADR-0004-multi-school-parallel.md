# ADR-0004：多流派并列，不做裁决

- 状态：已接受
- 日期：2026-09-14
- 相关：[ADR-0003](ADR-0003-jie-zhongqi.md)、[规则集与证据分级](../rule-sets.md)

## 背景

四柱里存在大量**没有唯一正确答案**的取值：换日基准（子正 / 子初）、大运顺逆（年干阴阳 / 只看性别）、
起运取整（精确 / 取整）、五行力量（计数 / 藏干加权）。这些是师承约定，不是实测数据，
任何一方都无法用天文或统计证据把另一方判为错误。

工程早期只有一套规则集，文档却声明「流派可并列」。这是一条**没有代码支撑的承诺**——
比不写更危险，因为它会让使用者以为分歧已经被处理过了。

## 决策

1. **并列而非裁决**。`compareSchools(input)` 对同一输入跑多套规则集，输出每派各自的命盘、事实图与规则指纹，
   外加逐字段的分歧清单。不返回 `answer` / `winner` / `recommended`，也不合并成「综合命盘」。
2. **分歧必须可枚举**。每个分歧点带两侧各自的 `ruleId` 与 `source`。
   只有当两侧取值确实不同时字段才进入 `divergences`，避免制造虚假分歧。
3. **分歧用参数表达，不用代码分叉**。`parameters.dayBoundaryMode`、`luckDirectionMode`、
   `luckStartRounding`、`hiddenStemWeights` 覆盖当前全部已知分歧。新增流派优先加参数取值。
4. **登记两套规则集作为活体验证**。`bazi-core-0.1.0`（通用派）与 `bazi-zichu-0.1.0`（子初派）在三处取值不同。
   没有第二套规则集，「可并列」就无法被测试，也就无法被信任。
5. **测试断言「至少两套」而不是写死数量**。新增流派是常规操作，不应导致测试失败。
   测试断言的是每套规则集各自自洽、指纹互不相同、分歧可枚举、一致项与分歧项并集完整。
6. **规则集声明引擎版本区间**。`engineCompatibility`（如 `">=0.3.0 <0.4.0"`）由审计强制校验，
   防止规则集与引擎版本静默错配。

## 后果

**收益**

- 文档承诺与代码能力一致，「可溯源」从单流派扩展到流派之间。
- 使用者能看到分歧本身，而不是被一个伪装成确定的答案误导。
- 新增流派成本固定：加一个目录、登记、跑测试。

**代价**

- 输出结构变复杂：调用方必须处理多份结果，不能再假设只有一个 `pillars`。
- 维护多套规则集意味着同一个 bug 可能要在多处修。这是「不合并」的必然代价，接受。
- `compareSchools` 的字段清单（`FIELD_EXTRACTORS`）需要随新分歧维度扩展，否则新分歧不会被列出。

## 未采用的做法

- **加权平均成综合命盘**：会造出一个任何流派都不承认的第三结果，且无法溯源。
- **默认取多数流派**：多数不是正确性证据，且会掩盖少数派取值。
- **只输出分歧不给 ruleId**：使用者无法自行复核，等于把裁决权偷偷留给实现者。
