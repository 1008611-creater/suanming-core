# ADR-0006：网页与引擎共用单一算法源

- 状态：已接受
- 日期：2026-09-17
- 相关：[ADR-0004](ADR-0004-multi-school-parallel.md)、[产品规格](../product-spec.md)

## 背景

网页最初自带一份手写八字实现（`web/bazi.js`）。它与 `src/` 各自演化，
结果两边算出的**月柱不一致**。用户看到的盘与引擎给出的盘是两套东西，
而首页写着「每个结果都标明计算口径与来源」。

这不是一次笔误，而是结构问题：**同一件事有两份实现，就一定会漂移**。
修一处的测试不会覆盖另一处，谁先被改取决于当天在改哪个文件。

## 决策

1. **算法源只有 `src/` + `rules/` 一份。**
   网页通过 `scripts/build-web-engine.mjs` 用 esbuild 打包成 `web/engine.js`，
   内嵌 `WEB_ENGINE_SOURCE_HASH`（路径 + 内容的 FNV-1a 指纹）与参与打包的文件数。
2. **删除 `web/bazi.js`。**
3. **新增 `web/engine-adapter.js` 作为唯一转换层**，只做形状转换与展示所需的
   少量派生（旬空、生肖、流年表），不重新实现任何历法或干支算法。
4. **`web/analysis.js` 退化为纯解释层**：只读入已算好的结果做评分与文案。
5. **用测试钉住同步**：
   `tests/web-engine-sync-smoke.js` 重新计算指纹与产物比对，
   源码改了却忘记重新打包时立即失败。

## 后果

- 网页与 Node 端**同输入必然同结果**，因为运行的是同一份代码。
- 打包产物是构建物，不手工编辑；`engine.js` 变更需要重新运行构建脚本。
- 页面偶尔需要展示引擎内部结构（如 `manifest`）时，必须通过适配层显式暴露，
  不能再在页面里另写一份取值逻辑。
- 包体增大到约 170 KB（未压缩），换来的是「只有一份真话」。可接受。

## 被否决的方案

- **保持两份实现，用测试比对**：只能比对已知样本，无法阻止新分支漂移。
- **页面直接 import 源码目录**：浏览器无法解析 Node 侧依赖与多文件 ESM 图，
  会引入构建期耦合到运行时。
- **把适配逻辑塞进引擎**：会污染「只算不解释」的分层，引擎输出将依赖渲染形状。
