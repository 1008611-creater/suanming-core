# ADR-0005：紫微斗数作为第二盘系

- 状态：已接受
- 日期：2026-09-14
- 相关：[ADR-0004](ADR-0004-multi-school-parallel.md)、[紫微斗数盘系](../ziwei-model.md)

## 背景

工程从 0.1.0 起就在 README 里写着「尚未完成：紫微斗数」。这条状态声明一直是对的，
但它同时暴露了一个更值得回答的问题：**这套架构到底是一个四柱程序，还是一个排盘平台？**

如果加紫微需要改时间层、改农历层、改事实图结构，那它就是前者，只是被写成了分层的模样。
如果加紫微只需要新增一个规则集目录、一个盘系目录、一组测试，那它才是后者。

另一个背景是：四柱与紫微在**同一份输入**上会给出不同的年、日口径。
四柱以立春换年，紫微以农历正月初一换年；四柱按子正或子初换日，紫微按晚子时进日。
把它们合并成一张「综合盘」，等于制造一个任何流派都不承认的第三结果。

## 决策

1. **紫微是并列盘系，不是四柱的派生层**。
   `castZiwei(input)` 与 `castBazi(input)` 平级，共用时间层（L0）与农历层（L2），
   但各自决定年界、日界与起盘依据，互不换算。
2. **规则集新增 `system` 字段**（`bazi` / `ziwei`）。
   分歧只在**同盘系内**定义：四柱与紫微的 `ruleId` 命名空间不同，
   互相比较会把「另一个盘系的全部规则」误报成分歧。`compareSchools()` 默认只并列同盘系规则集。
3. **宫名别名显式登记，而不是统一改名**。
   同一宫通行派称「交友」，古法称「奴仆」，参照实现 `iztro` 用「仆役」。
   改名会让历史结果与新结果对不上；不登记别名则会让逐宫比对报出大量假差异。
   折中做法是保留通行派名称，把别名写进 `palaceNames.aliases` 并导出 `palaceNameAliases()`。
4. **星曜规范顺序写进规则集**（`starOrder`）。
   不排序的话，同宫星序会随安星函数的书写顺序漂移，外部逐宫比对时全是假差异。
   顺序是约定（`evidence: convention`），不是传统口诀。
5. **未纳入的杂曜一律不做**。
   年、月、日、时系杂曜二十余颗，以及长生、博士、将前、岁前十二神，全部留待有可核对出处时再加。
   盘上多一颗来源不明的星，比少一颗更危险——它看起来同样确定。
6. **性别缺失时留空，不取默认值**。
   大限与小限需要性别。未提供时返回 `null`，而不是按男性计算：
   编造默认值会让「男顺女逆」静默变成男命结果，且调用方无从察觉。
7. **引入 `iztro` 作为交叉验证参照，但不作为证据来源**。
   `iztro`（MIT）登记为 `reference-implementation`，用于逐宫核对安星结果。
   它不改变传统口诀的 `evidence: traditional` 类别，也不会把「与某个实现一致」写成正确性证明。

## 后果

**收益**

- 架构命题得到验证：新增盘系的成本落在数据层与新增目录，时间层与农历层未改口径。
- 事实图、规则审计、版本清单、确定性指纹这些不变量对两个盘系同样成立，
  `auditFactGraph` 改为按清单里的规则集解析盘系，不再硬编码四柱默认集。
- 宫位、星曜、四化、大限、小限全部可溯源到 `ruleId`，与四柱同一套审计口径。

**代价**

- `compareSchools()` 的语义收窄为「同盘系内并列」。跨盘系对比需要另设入口，
  不能复用现有的分歧枚举结构——它们的字段根本不同构。
- 紫微规则集的 `confidence` 普遍低于四柱的天文层（0.68—0.9），
  这是如实反映传统口诀的确定性，而不是实现质量问题。
- 引入了一个外部参照实现作为验证依赖。它只用于测试与文档，不进入运行时依赖。

## 未采用的做法

- **把紫微合并进 `castBazi` 输出**：会让两套年界、日界在一个结构里互相污染，
  且无法分别标注各自的 `ruleId`。
- **统一宫名到某一派**：会让历史结果与新结果对不上，等于静默改口径。
- **先安上全部杂曜再补出处**：会把「不确定」伪装成「已确定」，
  与「结论必须可溯源」这条核心不变量直接冲突。
- **默认性别为男**：会让一半使用者拿到看起来正常、实际错向的限运结果。
