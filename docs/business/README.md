## 本地出报告工具（客户资料不出本机）

在仓库根目录执行 `npm run report`，浏览器会打开本机回环地址上的报告底稿页。
它复用线上同一份引擎产物，把 18 节模板里的结构部分自动填好，你只需要写
**§〇 验证结果与认账** 与 **§十六 可核验前瞻** 这两章必填内容，然后在浏览器里
打印或另存为 PDF。

- 页面地址只在本机回环（`127.0.0.1`），不联网、不上传、不写入本地存储；
  客户出生信息与盘面只在这台机器的浏览器里。
- 端口默认 8123；被占用时用 `npm run report -- --port 8231` 换一个。
- 生成的 PDF 与填写的底稿属于客户资料，**留在本地、不入库**。
- 判词与结论由你判断并负责；工具只摊开结构与规则依据，不给结论。

## 一句话商业模式

**不卖「算命」，卖「可验证的命理分析」。**

三条差异化：

1. **先验前事** —— 先说已发生的事让客户打分，**验不准不收费**（转化钩子）
2. **敢认账** —— 判错的部分写进报告，注明错因（信任壁垒）
3. **可核验前瞻** —— 未来给到具体月份，到期主动回访对账（复购引擎）

## 三条不能碰的线

1. **不吓唬人** —— 不说「大灾」「破财」「必死」。做「顺水逆水」的判断，不做命运判决。
2. **不越界** —— 医疗、投资、法律一律不碰；涉及健康注明以专业机构意见为准。
3. **不泄露** —— 客户没勾授权，一个字都不能用于素材；重大事件（去世、重病、离婚）即使脱敏也不写。

## 为什么这套能成（实证）

本包来自一次真实的逐条验证过程（案例原件属客户资料，**只留本地、不入库**）：

- 首轮前事清单里，客户标「不像」的条目占了多数 —— 说明首轮读法有系统性偏差。
- 经逐条核对、修正读法、公开认账后，客户对后续条目的评价转为「挺准」。
- 过程中出现 3 次系统性误判，**全部如实记录并认账**，客户信任反而上升

**结论：承认不确定、承认错误，不会削弱可信度，反而建立可信度。**
这就是这个生意唯一的、也是最难被抄的壁垒。

## 与线上产品的关系

本目录的「前事验证」流程与线上免费页面是同一套口径：

- 线上：<https://suanming.cauai.fun/check.html> 给出 5–8 条带推导依据的前事清单，
  用户逐条打标，页面只汇总条数。
- 线下：`pricing-and-delivery-sop.md` 的判定表按同一份清单的条数分布决定是否推进或退款。

两份产物都由同一个引擎与同一份规则集产出，不存在「线上一个说法、线下另一个说法」。
