# 实施计划

按「每阶段都有可验证退出条件」推进。阶段未达成退出条件不进入下一阶段。

## 阶段 0：基线（已完成）

目标：能算出盘，且结果可复现、可追溯。

- 交付：`src/` 时间层 + 四柱 + 紫微 + 规则集 + 事实图 + 版本清单。
- 退出条件：`npm test` 全绿；`validateTraceability` 通过；README 明确列出未完成项。

## 阶段 1：计算正确性修复（已完成）

目标：把已知会算错的边界修掉，并留下防回归的证据。

- 月柱子月/丑月月干错位 → 按节气序列位置重算，279 个日期交叉验证 0 处不一致。
- 真太阳时缺均时差 → 补齐 `equationOfTimeMinutes`，四柱与紫微共用。
- 边界样本：立春前后、辰巳交界、跨日、闰月。
- 退出条件：新增 3 个反例测试文件全绿，黄金样本四柱稳定。

## 阶段 2：网页与引擎合并为单一算法源（已完成）

目标：网页不再自带第二份算法。

- 新增 `scripts/build-web-engine.mjs`：把 `src/` + `rules/` 打包为 `web/engine.js`，内嵌源码指纹。
- 新增 `web/engine-adapter.js`：契约输出 → 页面视图模型，只做形状转换。
- 删除 `web/bazi.js`；`app.js` 改为 ESM 并 import 适配层。
- `web/analysis.js` 明确为纯解释层，旺衰阈值按口径分表。
- 退出条件：`web-engine-sync-smoke` 与 `web-adapter-smoke` 全绿；真实浏览器黄金盘正确。

## 阶段 3：产品完整度（已完成）

目标：首页承诺的能力在页面上都能看到。

- 紫微斗数盘面展示（十二宫、主星/辅星/杂曜、生年四化、大限、命身主）。
- 结果区标注引擎版本、星历模型、规则集与指纹。
- 页面免责声明与口径说明常驻。
- 退出条件：`docs/acceptance.md` 的 B 组全过。**已达成**：Edge 实测 24 项断言全绿。

## 阶段 4：质量门与自动化（已完成）

目标：不靠人肉记性维持质量。

- `npm run verify` = 全量测试 + 重新打包引擎 + 隐私扫描 + 产物完整性。
- CI 改为 `npm run verify`。
- 退出条件：本地与 CI 同绿；故意改一行源码后 verify 必须失败。**已达成**：
  改 `ENGINE_VERSION` → `web-engine-sync` 因指纹不一致失败；改月柱公式 → 5 个测试失败。

## 阶段 5：上线与验收（已完成）

目标：用户能在线上亲眼看到。

- 同步 `web/` 到服务器，配置入口 HTML 不缓存、静态资源短缓存。
- 验证 HTTPS、证书、静态资源、线上黄金盘。
- 退出条件：`docs/acceptance.md` 的 C 组全过。**已达成**：线上黄金盘与本地逐字一致，
  入口改为 `no-cache, must-revalidate`，避免部署后仍吃旧缓存。

## 阶段 6：真实可用性修复（已完成）

目标：把「首页承诺的能力」与「页面实际能算出来的东西」对齐，并主动排查真实缺陷。

- **姓名五格**：康熙笔画表从 294 字扩到 20778 字（CJK 基本区覆盖 98.98%），
  「张三」「欧阳娜娜」这类真实姓名不再报「未收录」；两源分歧逐字标注异说。
- **未来出生年份**：流年表上界与页面筛选区间改从出生年起算，虚岁不再为负。
- **合婚性别称呼**：同性别组合不再被硬编码成「男方/女方」。
- **盘面自检页**：`web/check.html` 落地首页「先验证已经发生的事」的承诺。
- 退出条件：`npm run verify` 全绿（35 项测试）；本地浏览器 50 项断言全绿。**已达成**。

## 阶段 7：持续演进（规划）

按价值排序的候选：

1. **规则集扩充**：接入更多流派，用 `compareSchools()` 展示分歧而不是覆盖。
2. **可分享结果**：生成只含计算结果的链接（不含隐私，需单独设计）。
3. **API 服务化**：把 `castBazi` / `castZiwei` 暴露为 HTTP 接口，带版本与指纹。
4. **解释层质量**：文案与评分模型的评估集，避免解释退化成通用套话。
5. **紫微限运补全**：斗君、流年流月流日流时四化与流曜（当前明确未完成，不伪装）。
