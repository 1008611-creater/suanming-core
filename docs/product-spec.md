# 产品规格：算得准（suanming-core / suanming.cauai.fun）

- 状态：生效
- 版本：0.6.3
- 最后更新：2026-09-21

## 1. 一句话定义

把传统命理做成**可解释、可复核、同输入同结果**的计算工具：先让用户验证已经发生的事，
再谈未来的选择。计算层不调用任何大模型，不使用随机数。

## 2. 用户

| 用户 | 场景 | 最在意 |
| --- | --- | --- |
| 好奇的普通人 | 输入生日，看自己的盘 | 页面能用、结果看得懂、不要玄乎到无法验证 |
| 认真的学习者 | 拿同一份生日对照不同派别结果 | 口径是否标注、能不能追到规则出处 |
| 研究者 / 开发者 | 用 API 或源码复算 | 确定性、结构化输出、可引用的事实图与版本清单 |

## 3. 产品范围

### 3.1 必须做（本版本）

1. **四柱八字**：年、月、日、时四柱；十神；藏干；旬空；生肖。
2. **真太阳时**：经度差 + 均时差；可切换为钟表时间；跨日样本日期必须正确。
3. **五行力量与旺衰**：分值、权重、口径、规则集标识全部随结果输出。
4. **大运**：顺逆、起运年龄、十步干支、起始年份。
5. **流年**：覆盖出生年至今年 + 11 年。
6. **紫微斗数**：十二宫、三层星曜、生年四化、四组十二神、大限、命主身主、五行局。
7. **命卦与八宅**：三元命卦、东西四命、八方吉凶。
8. **姓名五格**：以康熙笔画为准，覆盖 CJK 基本区 98.98%（20778 字）；
   只有真正未收录的字形才提示，且区分「未填姓名 / 字数不支持 / 某字未收录」三种原因。
9. **合婚**：年支关系 + 五行互补评分，标注为传统参考维度。
10. **可追溯**：每个结果带引擎版本、星历模型、规则集与指纹。
11. **地支关系派生**：六冲、六合、三合与半合、相刑（含自刑）、六害、旬空六类关系
    由引擎确定性派生，每组关系带自己的 `ruleId`；缺表即整组跳过，不回退默认值。
12. **前事验证（免费公开）**：由已经算出的结构生成 5–8 条可核对的前事方向，
    每条含判词、推导依据（宫位／十神／关系／`ruleId`）、程度三档（轻／中／重）与
    不确定性说明；用户自行打标，页面只汇总条数，不折算任何比例。
    判词与依据栏里的关系名一律用规则集登记的中文名（`子午冲`、`子丑合土`、`寅巳害`）；
    内部英文枚举（`clash` / `harm` / `void`）不上页面。一条跨柱关系只在
    **最早一个在清单里有条目的宫位**完整展开，其它相关宫位只以「共见」引用，
    避免同一句话在清单里写两遍。
    判词只说盘面结构，以及可以拿自己经历核对的具体方向（父母长辈、婚姻合作、收入职位、学习证件、同辈分财等）；
    不出现内部规则编号、档位字样和「结构性 / 摩擦性」这类说法。程度档单独显示。
13. **本地出报告**：复用同一份引擎产物，按模板 18 节填坑，浏览器直接打印成 PDF；
    客户数据不出本机。
14. **隐私**：真实出生资料、地址、私人命盘不进版本库，也不进公开页面；
    业务文档可公开入仓，真实案例与客户资料只留本地。

### 3.2 明确不做

- 不把概率性、流派依赖的解释包装成确定事实。
- 不给医疗、法律、投资、生命安全的结论。
- 不把四柱与紫微合并成一张「综合盘」——历史上没有哪个流派承认这个产物。
- 不用大模型生成干支或历法数据。解释层可以生成文字，但不得重算盘。
- 不在任何面向用户的位置出现百分比、「准确率」「命中率」这类比例承诺；
  用户打标只汇总条数。
- 不做事后夸功（事情发生后回头说「早就说过」），不用恐吓性表述驱动付费。

## 4. 关键产品承诺与验证方式

| 承诺 | 验证方式 |
| --- | --- |
| 同输入同结果 | `tests/determinism-*`、`compareSchools()` 逐字段比对 |
| 每个结论可溯源 | `validateTraceability(chart).valid`，事实必须带 `rule_id` |
| 网页与引擎同一份算法 | `tests/web-engine-sync-smoke.js`（源码指纹比对） |
| 页面字段不会与引擎脱节 | `tests/web-adapter-smoke.js`（黄金盘 + 字段断言） |
| 真太阳时正确 | `tests/true-solar-time-smoke.js`（8 组含跨时辰、跨日样本） |
| 月柱无系统性错位 | `tests/month-pillar-invariant-smoke.js`（120 组全表） |
| 四柱与独立实现一致 | `tests/bazi-cross-reference-smoke.js`（随机抽 10 份盘与独立实现比对，四柱一致率 100%） |
| 关系派生可追溯 | `tests/relations-smoke.js`、`tests/relations-missing-table-smoke.js`（缺表整组跳过） |
| 前事清单确定性且合规 | `tests/past-events-smoke.js`（条数 5–8、同输入逐字一致、文本无百分比与「准确率」、判词不重复、关系名只出中文、展示文本不含内部英文枚举） |
| 页面在真实浏览器里可用 | 发布前手工浏览器验证清单，见 `docs/acceptance.md` |

## 4.1 核心用户流程

1. 用户打开首页，阅读免责声明后进入排盘页。
2. 用户填写合成或真实但不保存的出生资料、经度和时间口径。
3. 页面校验输入；通过后调用同一份网页引擎，展示四柱、紫微、规则集和来源指纹。
4. 用户可进入前事验证页，先用已经发生的事核对盘面结构：页面给出 5–8 条带推导依据的
   前事方向，用户逐条标「像 / 不像 / 不确定」，汇总只显示条数，不折算比例；
   再核对出生时辰、流年回看与紫微三方四正。页面不替用户下吉凶结论。
5. 需要完整报告时，用户在本地运行出报告工具，按模板 18 节生成可打印页并另存为 PDF；
   客户数据不出本机。
6. 用户可清空表单并重新输入；页面不把资料写入仓库或公开链接。

## 4.2 失败流程

- 日期、时间、经度或性别非法：在排盘前提示具体字段错误，不生成部分命盘、不静默使用默认值。
- 姓名为空、字数不支持或存在未收录字：分别提示原因，不编造笔画。
- 引擎或静态资源加载失败：页面显示可理解的失败提示；质量门和浏览器验收必须发现控制台异常。
- 规则集未登记某项能力：按架构约束整组跳过并标注未提供，不补默认值伪装完成。
- 发布后黄金盘漂移、入口异常或隐私泄露：停止扩大发布范围并执行 `docs/rollback.md`。

## 5. 非功能要求

- **确定性**：无随机数、无当前时间参与的盘面计算（流年表取「今年」属展示层，可复现的条件已写入规格）。
- **可离线**：核心计算无网络依赖；网页版为单个 ESM 产物，可从任意静态服务器提供。
- **分层**：计算（L0–L3）与解释（L4）严格分离，解释层不得包含历法算法。
- **中文优先**：输出面向中文用户；代码标识与注释用中文说明设计意图。

## 6. 成功标准

1. `npm run verify` 全绿，且 CI 与本地结果一致。
2. 网页首页与排盘页在桌面、窄屏、慢网下都能出结果，且控制台无错误。
3. 任意一份盘都能回答「这个字是按哪条规则、哪个版本算出来的」。
4. 随机抽 10 份盘与独立实现交叉验证，四柱一致率 100%。
