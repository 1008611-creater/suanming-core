## 边界回归

- **换日边界**：2005-07-13 凌晨 02:00（北京）对应 UTC 前一天 18:00。日柱必须按出生地民用日计算，用 UTC 日序会整体错一天，已固化为回归用例。
- **节气边界**：出生时刻跨越节气瞬间时，年柱与月柱必须同时切换。
- **时辰边界**：真太阳时每两小时一时辰，子时起于真太阳时 23:00。
- **流派边界**：换日基准切换时，日柱与时干必须同步切换。测试断言子初派 23:30 的日柱与时干都不同于通用派，
  且通用派在 23:30 仍与同日 08:58 同柱——只改日柱不改时干是最容易漏掉的错法。
- **朔日边界**：农历月从包含朔时刻的民用日零点起算，不按朔的瞬间切分。
- **早晚子时**：紫微子时分早晚（索引 0 与 12），命身宫取地支后同宫，但起紫微星按晚子进日。
  闰月前十五日与十六日起宫不同，晚子时不参与该修正——三条口径必须同时成立。
- **跨时辰经度**：东经 75° 出生者的钟表读数会整体偏移一个时辰，紫微必须用真太阳时判定时辰索引。
- **日系杂曜基准**：三台、八座、恩光、天贵以左辅右弼文昌文曲的**实际落宫**起算，
  日序用「晚子取当日、其余取前一日」。这一位之差会让四颗星整体错宫，已由杂曜测试逐宫断言。
- **命主身主**：两者取支口径不同（命宫支 / 生年支），基准盘命宫卯、身宫亥、生年支酉
  恰好能把两种口径区分开——按身宫取会得「天机」，按生年支取得「天同」。
- **十二神起宫与方向**：长生随五行局、博士随禄存、将前随年支三合、岁前随年支宫；
  前两组的方向依赖性别，缺性别时必须留空而不是默认男命。

## 多流派并列的可验证性

「流派可并列」不是一句声明，而是可以被测试的事实：登记了至少两套规则集，每套独立通过规则审计与溯源校验，
指纹互不相同，分歧逐字段可枚举，一致项与分歧项并集等于全部对比字段。
返回结构里不存在裁决字段——这条红线由测试断言，避免后续版本悄悄引入「综合答案」。

并列**只在同盘系内成立**：四柱有 `pillars`、紫微有 `palaces`，字段不同构。
`listRuleSets({ system })` 与 `compareSchools()` 都按盘系过滤，跨盘系比较不会被当成流派分歧。

## 盘系并列的可验证性

紫微作为第二盘系引入后，以下不变量对两个盘系同时成立，且由 `tests/dual-system-smoke.js` 断言：

- 同一输入分别排四柱与紫微，两者各自通过结构与溯源校验，事实图互不引用对方的 `ruleId`。
- 两盘年界口径不同（立春 vs 农历正月初一），同一输入可以给出不同的年干支——这是**正确行为**，不是矛盾。
- 紫微规则集不进入四柱的 `divergences` 计算，四柱流派数量不因新增盘系而变化。

## 确定性

同一输入必须得到同一输出，用内容指纹验证（`hashInput` / `hashFacts`）。指纹与对象键顺序无关，因此可以被外部独立复算比对，而不是只能信任本工程的自述。

## 跨实现交叉验证

黄金测试能发现「算错」，但发现不了「整体口径偏移」——比如某颗星按年支还是按年干取、
晚子时进不进日、闰月十六日后算不算下月。这类差异往往只在特定年份或时辰才暴露，
因此除了单张基准盘，还必须有**多张盘的交叉验证**。

紫微层与 `iztro` v2.6.1 官方打包产物对照，参照结果覆盖 1949—2030 年、12 个不同时辰、
男女各半、含闰月年与跨年边界。逐宫比对内容：三层星曜、四组十二神，外加全盘五行局、
命宫、身宫、命主、身主。

这层验证的期望值**硬编码在 `tests/ziwei-cross-reference-smoke.js`** 里，
不依赖任何外部参照目录，CI 可独立复现——否则「验证过」就变成一句无法被检验的自述。

## 测试入口

npm test
