# 验证策略

## 分层误差预算

不同层的误差不能混成一个「准确率」：

| 层 | 验证对象 | 证据 | 当前结果 |
| --- | --- | --- | --- |
| L1 天文 | 节气时刻 | 紫金山天文台 / 香港天文台公布时刻 | 17 个样本平均绝对误差 13.3 秒 |
| L1 天文 | 章动 | Meeus 例 22.a | 完全吻合 |
| L1 天文 | 太阳黄经 | Meeus 例 25.b | 差 0.26″ |
| L1 天文 | 月相 | Meeus 例 49.b | 完全吻合 |
| L0 时间 | 时区与夏令时 | ICU tzdata + 中国 1986—1991 夏令时表 | 1988-07-01 解析为 UTC+9 |
| L2 农历 | 月序、闰月、换日 | 公开发布的春节/端午/中秋/闰月日期 | 16 个黄金用例全部通过 |
| L3 四柱 | 日柱锚点 | 公开万年历 | 1900-01-01 甲戌、1949-10-01 甲子、2000-01-01 戊午、2024-01-01 甲子 |
| L3 四柱 | 时柱天干 | 五鼠遁全表 | 10 日干 × 12 时辰逐项校验 |
| L3 四柱 | 月柱天干 | 五虎遁 | 10 年干逐项校验 |
| L3 四柱 | 年柱/月柱边界 | 立春与节气瞬间 | 2024-02-04 16:00 → 癸卯/癸丑，17:00 → 甲辰/丙寅 |
| L3 四柱 | 流派并列 | 两套规则集各自独立溯源 | 每派事实图单独通过 `validateTraceability`，指纹互不相同 |
| L4 事实 | 分歧可枚举 | 逐字段比对，两侧取值确实不同 | 23:30 出生暴露日柱／时柱分歧，其余字段归入一致项 |

传统约定的取值（大运顺逆、起运算法、藏干表）**没有**实测误差预算，只标注体系内部的置信度，见 [rule-sets.md](rule-sets.md)。

## 边界回归

- **换日边界**：2005-07-13 凌晨 02:00（北京）对应 UTC 前一天 18:00。日柱必须按出生地民用日计算，用 UTC 日序会整体错一天，已固化为回归用例。
- **节气边界**：出生时刻跨越节气瞬间时，年柱与月柱必须同时切换。
- **时辰边界**：真太阳时每两小时一时辰，子时起于真太阳时 23:00。
- **流派边界**：换日基准切换时，日柱与时干必须同步切换。测试断言子初派 23:30 的日柱与时干都不同于通用派，
  且通用派在 23:30 仍与同日 08:58 同柱——只改日柱不改时干是最容易漏掉的错法。
- **朔日边界**：农历月从包含朔时刻的民用日零点起算，不按朔的瞬间切分。

## 多流派并列的可验证性

「流派可并列」不是一句声明，而是可以被测试的事实：登记了至少两套规则集，每套独立通过规则审计与溯源校验，
指纹互不相同，分歧逐字段可枚举，一致项与分歧项并集等于全部对比字段。
返回结构里不存在裁决字段——这条红线由测试断言，避免后续版本悄悄引入「综合答案」。

## 确定性

同一输入必须得到同一输出，用内容指纹验证（`hashInput` / `hashFacts`）。指纹与对象键顺序无关，因此可以被外部独立复算比对，而不是只能信任本工程的自述。
