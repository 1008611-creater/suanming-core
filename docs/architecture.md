# 架构

## 分层

部署入口 `app/` 位于仓库工作区根目录，是 `web/` 的同步镜像，不是新的代码层。由
`scripts/sync-deployment-mirror.mjs` 统一生成；修改网页必须先改 `web/`，再通过
`npm run verify` 同步，避免实际部署入口与仓库内网页漂移。

| 层 | 职责 | 关键约束 |
| --- | --- | --- |
| L0 时间 | 公历、UTC、IANA 时区、中国历史夏令时、真太阳时 | 全部用儒略日运算，不用 JS `Date` 做算术 |
| L1 天文 | VSOP87D 太阳视黄经、IAU1980 章动、Delta-T、节气、月相 | 保留误差预算与不确定度，不外推超过模型有效范围 |
| L2 农历 | 朔日锚点、月份区间、中气判断、闰月候选 | 只输出天文事实，历法显示留给上层 |
| L3 排盘 | 并列盘系：四柱与大运（`bazi`）、紫微斗数十二宫与限运（`ziwei`，含 66 星与四组十二神） | 全部取值来自规则集，代码不内嵌流派字面量；盘系之间不互相换算；规则集未登记的能力整组跳过而非补默认值 |
| L4 事实 | 事实图、规则溯源、输入与事实指纹、同盘系多流派并列 | 每个结论必须带 `rule_id`、`source`、`confidence`、`evidence`；流派分歧只并列不合并 |
| L5 解读 | 只消费事实图，输出可审计结论 | 引用不到 `fact_id` 的结论被直接丢弃 |
| L6 接口 | CLI、API、应用适配 | 结果必须携带 `manifest` |

## 核心不变量

1. **确定性**：同输入 + 同引擎版本 + 同星历版本 + 同规则集指纹 → 同输出。指纹见 `src/derive/hash.js`，可被外部复算验证。
2. **可溯源**：结论不能凭空出现。`explain()` 会丢弃没有事实来源的结论；`validateTraceability()` 会拒绝置信度高于其规则的结论。
3. **盘系可并列**：规则集带 `system` 与指纹。四柱与紫微是两套并列盘系，共用 L0 时间层与 L2 农历层，
   但年界（立春 / 正月初一）、日界（子正或子初 / 晚子进日）各按自己的口径，**不互相换算**，也不合并成一张综合盘。
   详见 [紫微斗数盘系](ziwei-model.md) 与 [ADR-0005](decisions/ADR-0005-ziwei-as-second-chart-system.md)。
4. **流派可并列**：同一盘系内可用不同规则集分别计算，结果各自标注来源，不合并成单一「正确答案」。
   `compareSchools()` 把分歧逐字段列出并附两侧 `ruleId` 与 `source`；**返回结构里没有 `answer` / `winner` / `recommended`**，
   测试会断言这一点。分歧用规则集的 `parameters` 表达，计算代码不分叉。详见 [ADR-0004](decisions/ADR-0004-multi-school-parallel.md)。
5. **隐私边界**：真实出生资料、地址、私人命盘不进入版本库。`.gitignore` 与 `SECURITY.md` 双重约束。
6. **展示时间显式化**：流年窗口的「今年」只属于页面展示层。`paipan({ asOfYear })` 接收显式展示年份；未传时按出生年生成固定窗口，避免核心输出隐式依赖系统时钟。

## 为什么解读层不能反向计算

如果解读层可以自行推算，那么它就能绕过规则集和事实图，输出没有出处却看起来确定的结论。
把「计算」与「解释」分成两层之后，任何解释都必须先声明它引用哪些事实，审计才有落点。

## 盘系之间不共享 ruleId 命名空间

`bazi.*` 与 `ziwei.*` 是两套独立的规则命名空间。分歧只在**同盘系内**相对参照规则集计算：
把紫微规则集与四柱规则集互相比较，会把「另一个盘系的全部规则」误报成分歧，清单随之失去意义。
因此 `listRuleSets({ system })` 与 `compareSchools()` 都按盘系过滤，`auditFactGraph()` 按事实图清单里的
`ruleSet` 解析盘系，而不是硬编码四柱默认集。

## 分歧的表达方式

流派差异不写成 `if (流派 === '子初')` 这类分支，而是下沉成规则集里的机器可读参数：

| 参数 | 分歧 |
| --- | --- |
| `dayBoundaryMode` | 子正换日 / 子初换日 |
| `luckDirectionMode` | 年干阴阳定顺逆 / 只看性别 |
| `luckStartRounding` | 起运年龄保留分数 / 取整 |
| `hiddenStemWeights` | 藏干计数 / 藏干加权 |

计算函数只读参数，不认流派名。新增流派优先加一个参数取值；只有当分歧无法参数化时才改计算代码，且必须补回归用例。
这样「加流派」的成本被固定在数据层，而不会随流派数量线性侵蚀计算层。

**新增盘系**的成本略高，但同样落在数据层：新增规则集目录 + 新增盘系目录 + 排盘入口，
L0 时间层与 L2 农历层原样复用。紫微的引入验证了这条边界——时间层与农历层一行口径都没改。

## 版本进入 manifest

`createManifest()` 记录引擎版本、星历模型、Schema 版本、规则集 ID、规则集版本与规则集指纹。
没有 manifest 的输出无法回答「这是哪一版算出来的」，因此视为无效结果。
